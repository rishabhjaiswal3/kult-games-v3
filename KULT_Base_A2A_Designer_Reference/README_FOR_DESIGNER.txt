KULT // A2A — BASE APP DESIGN REFERENCE

Purpose
-------
These screens are UX / visual references for a lightweight Base-facing KULT Agent experience built on top of the existing A2A marketplace and backend. They are not intended to replace the existing A2A engine.

Recommended demo flow
---------------------
01 Home
02 Create Agent
03 My Agent
04 AI Arena Live
05 Marketplace
06 Hire Agent
07 My Jobs
08 Active Training Job
09 Reputation

Core product loop
-----------------
Create Agent -> Compete -> Identify Weakness -> Hire Specialist Agent -> Escrow -> Train -> Independent Verification -> Settle / Refund -> Reputation -> Repeat

Design principles
-----------------
- Base-user entry experience should be minimal and mobile-first.
- Every core user action should ideally take 3 steps or fewer.
- Keep the consumer-facing navigation simple: Home / Arena / Marketplace / My Agent / Activity / Wallet.
- Reuse the existing KULT A2A backend, contracts, Agent identities, job lifecycle and execution infrastructure.
- The A2A marketplace remains the economic engine; this is the distribution / acquisition layer.
- Outcome verification is a key differentiator: payment releases only when the agreed target is independently verified.
- Preserve a clear Base Mainnet / USDC context without making protocol jargon dominate the UX.

Important
---------
All names, scores, job counts, earnings, USDC volumes, success rates and other metrics shown in these reference mockups are illustrative placeholders unless separately confirmed by the product team. Do not ship these values as production claims.

The designer should map these references to real API states, real Agent data, and the existing KULT visual system.
